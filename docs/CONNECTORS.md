The candidate pins `quorumrelay==0.1.0.dev4` to the included wheel, SHA-256 `f0f9bc97d549785458d8ac1d879258dc7750d5d420b1c9043d97026b41187ee1`, built from core commit `58d609c960212b62504d4d320e11c238e5bb221e`. The lockfile records that exact hash. The package retains 31 provider families and 34 baseline source/input pairs; those counts are parsing coverage, not a claim that every provider has complete live discovery, native search, export or writes.

## Account read fields and limits

CivicPlus Essential uses provider `municode-meetings`, origin `https://meetingsgov.devmunicode.com` (the documented dev host only), and an explicit application-owned namespace. TelVue uses provider `telvue`, origin `https://connect.telvue.com`, and an explicit account namespace. Leave their source `options` empty unless configuring an existing SDK-supported download origin; do not put credentials in source options, saved files, fetch forms or request JSON.

Essential fetch fields are `api_resource: meeting|item|multimedia` with a supplied `external_id`, or `api_resource: collection` with explicit nonnegative `offset` and exact `filters`: `Words`, `CreatedMeetingFromDate` and `CreatedMeetingToDate` (each `{Day, Month, Year}` integers), `ArchivedState` (`-1`, `0`, `1` or `2`), and `MeetingTypeIds` string array. No offset stride or response envelope is guessed. Meeting/item/collection responses whose schema is undocumented remain exact raw partial captures without inferred normalized meetings. Multimedia preserves the documented structure and supplied parent meeting relationship. No exact native text-search semantics are claimed for Words.

TelVue fetch fields are `api_resource: media|videos|playlists`; only media and playlists accept an optional decimal `external_id`. The SDK preserves transcript text, chapters, provider IDs, source metadata and unknown fields. API listing pagination/end conditions and account visibility remain unverified. A media upload date is not inferred to be a meeting date.

Trusted Essential credential configuration is keyed by `municode-meetings` and requires `origin`, `tenant`, exact `namespace` (or `allowed_namespaces` list), and `token`. TelVue is keyed by `telvue`, with the same binding fields plus `access_key` and `secret_passphrase`. `tenant` must exactly match this application's context tenant described below. Both APIs fail closed for mismatched origin, tenant, namespace, revoked grants and redirects. No token is issued by these consumers, and no test account credentials are included.

Wistia uses `https://api.wistia.com/modern/medias`, its existing SDK-derived namespace, optional source `options.page_size` and `options.folder_id`, and private `wistia_token`. The SDK offers media listing/detail, supplied captions, and bounded native media/transcript-excerpt search; consumer search screens described here search captured local records. Neither complete transcript availability nor live account acceptance is implied. Legistar read credentials use `legistar_token`; Repository v2 reads use `laserfiche_token`. Provider write credentials are separate provider dictionaries governed by server policy.

## Evidence boundaries

Synthetic fixtures verify shared parsing, identity/state handling and consumer integration without mutating a live vendor. Account credentials, tenant-specific permissions/enums and live write/readback acceptance remain absent. Keep partial results, unknown bodies/dates, unavailable attachments and raw captures visible; do not call them complete catalogs or successful content generation. Human review and existing publication controls remain required. This branch is a draft integration candidate, not a release or publication request.

## Configure and run TownRecord

From `core`, run `uv sync --locked`. The app uses its existing authenticated local API/job lanes and SQLite service; it does not start a separate connector server. `/v1/connectors/ui` is a bearer-protected local panel. `/v1/connectors/capabilities` reports the complete provider roster and operation evidence. The legacy PrimeGov path remains the default for sources without a connector configuration.

An existing accepted `meeting_portal` source can be configured with `PUT /v1/connectors/sources/{source_id}` using `provider`, optional `namespace`, `body`, `input_format`, validated `options`, and `bounds`. Its existing source origin supplies the URL. Other source settings are retained. The namespace is SDK-derived for public tenant sources; Essential/TelVue account APIs require the explicit application account namespace above. Bounds include explicit date/page/record/parser/transfer/deadline limits; configured transfer bytes cannot exceed the application's existing packet limit.

`POST /v1/connectors/sources/{source_id}/sync` queues existing job lanes with explicit `from_date`/`to_date`, an optional saved `content_base64`, or an account-only `fetch_fields` object using the documented fields above. Account fetch cannot be combined with a saved capture or date window. `/v1/connectors/jobs/{job_id}` and its cancel route retain progress, checkpoint and cancellation state. The shared migration stores exact captures, scoped records/state, source/destination links and evidence. Existing destination IDs and the legacy path are preserved; no meeting is invented from unknown raw account responses.

Process-owner `TOWNRECORD_CONNECTOR_CREDENTIALS` contains the trusted credential JSON. Account `tenant` must equal the source's jurisdiction ID converted to a string. Read contexts forward only the configured provider dictionary and its known flat read-token key; a different provider's credentials are not forwarded. Credentials cannot be supplied by sync/configuration request JSON. API bearer tokens remain TownRecord authentication and do not by themselves grant provider write permission.

Search uses `/v1/connectors/sources/{source_id}/search?q=TERM&phrase=PHRASE` over captured local records. Export uses its `/export?format=zip` route, streams a scoped artifact and reports the SHA-256 header. Existing record capture, download, transcript/caption and document processing remain their own jobs; missing content does not become successful extraction.

Provider plans and commits are separate queued routes. The process owner grants exact `write:plan`/`write:commit` permissions to a TownRecord token ID using `TOWNRECORD_CONNECTOR_WRITE_GRANTS`; usable provider credentials and meeting/resource policy are also required. Commit requires the exact reviewed plan ID/hash. The `TOWNRECORD_CONNECTOR_WRITES_ENABLED` setting can disable adapters. Ordinary source sync never commits a provider write. Migration/rollback acceptance must preserve the existing database and source/destination identity; do not use the integration to replace production data.
